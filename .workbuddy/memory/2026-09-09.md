## 修复：题库练习顶栏「更多操作」菜单点击无反应

背景：工作区把练习顶栏的自定义 overflow 面板改成了思源原生 `Menu`（新增 `practice-overflow-menu.ts`），改完点击 Ellipsis 无反应。

排查要点（思源 3.8.2，`vendor/siyuan/app/src/plugin/Menu.ts`）：
- 插件 API 的 `Menu` 构造是 `constructor(id?: string, closeCB?, independent = false)`；传 id 时会写 `commonMenu` 的 `data-name`，再次 `new Menu(同 id)` 被判定为 `isOpen = true`，**addItem / open 全部 no-op**。一旦上次菜单没走正常 remove 路径，`data-name` 残留 → 该入口永久失效。
- 内部 `SiyuanMenu`（`app/src/menus/Menu.ts`）只有 `popup()`，`open()` 是插件 API 层的包装；写自定义菜单时优先 `open`，可留 `popup` 兜底。
- 菜单项过滤 `applyMenuEntryVisibility` 只认思源内置 `data-name`（`entryScope`），插件自定义菜单名不会被误过滤，可以给菜单起名字。

改动：
- `src/lets-question-bank/practice/PracticeHeader.svelte`
  - `new Menu(id)` → `new Menu(undefined, closeCB)`，toggle 状态自己用 `overflowMenu` 变量维护（点击已打开的入口 → `close()`）。
  - 不再依赖 `event.currentTarget`（Svelte 5 委托事件），改用 `bind:ref={overflowTrigger}` + `closest("[data-practice-overflow-trigger]")` 兜底。
  - 移动端 `menu.fullscreen()`（与 `src/index.ts` 顶栏菜单一致）。
  - `open`/`popup` 双入口；整体 try/catch + `getLogger("practice-overflow")` + `showMessage` 兜底，失败不再静默。
- `src/lets-question-bank/practice/QuestionBankPractice.svelte`：删除未使用的 `practiceHeaderActions` prop/import（svelte-check 警告）。
- `src/test/siyuan-browser-mock.ts`：`Menu` mock 升级为记录式（items/opened/closeCB，暴露 `globalThis.__damophusLastMenu`），原生菜单在浏览器测试里可断言。
- `src/lets-question-bank/question-bank.browser.test.ts`：新增 `clickOverflowItem()`，把依赖旧 DOM 菜单的「无限练习模式」用例改成走记录式原生菜单。

## 修复：flashcard onload 报 "toolbar-action:locate is already registered"

根因：`plugin-registry.initializeEnabledPlugins()` 在每次主插件 `onDataChanged` 时都会对已启用子插件**再调一次** `onload()`（无守卫假设）。`lets-flashcard` 的 `onload()` 第一句就 `registerReviewToolbarActions()` → 8 个 `toolbar-action:*` contribution 在模块级 `contribution-registry.ts`（`Map` 单例）里撞 id → 抛错 → onload 后半段（eventBus 绑定、runtime.load、entry 创建等）全部跳过。多数其它子插件靠 `if (this.listening/registered)` 守卫逃过一劫，flashcard 漏了。

改动（`src/lets-flashcard/index.ts`）：
- `onload()` 开头加 `flashcardBooted` 守卫（question-bank 同款模式），`onunload()` 开头重置。
- `registerReviewToolbarActions()` 注册前先 splice 掉旧 disposers 再注册（dispose-first 防御，双保险）。

验证基线方法（ reused）：`git show HEAD:<file> > <file>` 临时回退 → 跑测试对比失败集合 → 用备份恢复。question-bank.browser.test.ts 的 6 个失败在 HEAD 与工作区一致，与菜单改动无关。
